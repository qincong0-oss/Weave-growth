# 产品共识

## 目标

面向柯桥面料企业，通过现有产品驱动持续客户开发，帮助企业获得有依据的售前结果，并把员工和 AI 的工作成果积累为公司知识。

当前 Demo 的商业目标是让纺织企业家看见值得试用的业务改善，并获得可以检验的反馈。演示兴趣不等于付费意愿，生成线索不等于收入。

## 用户已经确定的方向

1. 保留持续售前入口，v0.3 按已讨论的推荐 PRD 新增订单确认、变更核对及轻量客诉证据演示。完整供应链托管、自动赔付与财务核销仍不展开。
2. 产品和经营资料接入后持续运行，取消每轮人工创建开发任务。
3. 客户背调是核心能力。除业务与采购角色，还需覆盖外贸回款风险、付款历史、实际交易主体、财务、司法/名单、贸易及付款条件；参考资信服务的专业维度。
   商业适配和账期批准分别判断。未知不等于低风险，所有信用条件由企业财务审批。
4. 同时发现现有产品销售机会、相邻应用机会与产品改进空间。
5. 反馈循环形成有来源、有范围的标准企业知识与上下文。
6. 企业已有 ERP、CRM 时保留其职责，证明增量价值。
7. GitHub 保存代码与项目共识，支持多位成员使用不同 AI 协作。
8. `@0xrelander` 为项目协调人，Nick 为产品与商业负责人。

## 曾讨论但已被替代的方向

“先创建开发任务再启动 AI”已由持续运行方案替代。全链条托管开发、自动报价和采购执行不作为首版卖点。不能再把通用 CRM 描述为仅能存储数据，也不能假定通用 AI 产品没有企业知识能力。

## 核心验证问题

匹配建议是否优于企业现有做法？背调的来源和采购角色是否准确？业务员是否接受交接？减少的工作时间是否超过审核与维护成本？产品机会能否得到独立需求支持？交付是否可以重复、能否支撑续费？

## 信息标准

企业确认事实、客户明确表达、公开观察与 AI 推断分开记录。知识至少带来源、时间、适用范围、负责人和确认状态。客户沉默不能解释为需求不存在；个别反馈不能直接推导市场趋势。

## v0.2 产品接入共识

优先接入企业已有 ERP/产品 API，无法直接连接时提供表格路径。Demo 已支持本地 CSV 的字段映射、校验、差异、待确认和版本历史；API 与规格单提取为明确标注的示例。资料来源、原始行、映射和确认人随产品保留，冲突不静默覆盖。

## v0.3 已授权的演示扩展

用户确认继续制作 Demo，并要求增加直击企业老板痛点、直观说明价值的视频或 HTML。本轮采用可分享、可暂停和重播的 HTML 故事。具体工作关联 Issue #3。

推荐的第一付费切口是订单确认包：从明确采购意向、PO、已确认规格和回复中发现差异，经职责人确认后导出。它是待试点验证的商业假设，不能把 Demo 的顺畅交互、订单金额或推算工时当成已实现收益。

老板故事突出三类面料问题：总幅与可用幅宽口径、样品认可范围、数量变更后的关联确认。售前和售中仍为分开的演示样本状态；页面跳转不代表已将真实需求写入企业 ERP。

开放代码组件的采用、自动解析准确率、多人审批及真实连接都仍属于未来试点。当前实现不安装推荐开源解析器或调用模型。
