# ADR 0002：把回款判断与产品接入补成完整售前流程

状态：已采纳。日期：2026-09-17。来源：产品负责人明确要求直接修改仓库并发布。

## 原因

仅展示品牌背景与产品适配，无法回答纺织外贸最关心的付款风险。产品库若只展示已有卡片，也无法说明企业现有 ERP、表格和规格单如何进入知识框架。

## 决定

1. 背调拆分为商业适配与账期依据两个判断。提供法律主体、采购/签约/付款链、应收核销、财务、司法与名单、贸易活动、付款条件、保险及复核证据。没有足够证据时保留未知，不生成回款概率或授信批准。
2. 信用数据帮助售前决策，不自动执行合同、投产、放货、收款或保险申请。销售交接包含未批准的信用状态，仍由企业财务决策。
3. 产品接入采用来源 → 字段映射 → 校验 → 待确认 → 资料负责人复核。API 与规格单是标注清楚的样例；CSV 实际在浏览器本地读取。
4. 保留企业料号、原始行、来源字段映射、旧产品版本和复核轨迹。冲突不静默覆盖；受影响草稿失效，人工确认后仍须重新生成。
5. 继续使用静态演示，不把用户资料上传公开仓库，不收集真实接口密钥。多企业权限、生产数据存储与实时信用源在 P1 实施。

## 边界与后续验证

样例并非真实征信结果。演示的未收金额测算不是预期损失，保险不从敞口中直接扣除。法定名单应根据适用法域和交易关系核验。本版本不提供真实企业的法律或信用判断。

真实试点应先取得一个 ERP 的授权导出与接口文档、一组应收核销数据、合法取得的信用报告；验证料号去重、会计口径、身份匹配、资料时效和使用权限。
