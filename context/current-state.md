# 当前项目状态

更新于 2026年9月18日。阶段为 v0.3 交互演示：保留持续售前，新增订单确认与轻量客诉证据。

## 已确定

现有产品是持续开发的入口。企业完成首次经营配置后，系统自主研究客户与机会，不要求每轮创建开发任务。客户背调、产品匹配、反馈沉淀和产品机会形成循环。

当前用户授权工作是制作 PRD、改进 Demo、建立 GitHub 共享项目、通过 GitHub Pages 公开上线演示，并指定 `@0xrelander` 为协调人。没有修改原站或发送真实客户邮件。

## v0.3 当前交付

本轮对应 [Issue #3](https://github.com/qincong0-oss/Weave-growth/issues/3)。用户授权继续实现研究支持的推荐 PRD，并增加直观说明老板痛点与产品价值的 HTML 演示。研究稿已纳入 `docs/order-confirmation-prd.md`；取舍见 ADR 0003。

- `#/orders`：一笔虚构面料订单，演示幅宽口径、数量单位、样品认可范围三项差异，逐项查来源、驳回错误推断、确认与澄清。
- 可编辑澄清草稿；内部批准、客户接受与 ERP 暂存回执分开记录。实际生成 JSON、Markdown 与 ERP CSV 下载，但未连接真实系统。
- 10,000 → 12,000 米变更使相关价格、交期、批准及草稿失效；保留无关事实、历史确认和历史导出。不把条件交期编造成固定交货日。
- `#/aftersales`：未来假设客诉。将主张、样品范围、缺失批次和检测资料区分；实际争议版本及责任保持未知，补证动作只生成模拟待办。
- `boss.html`：六幕独立 HTML，讲述订单风险、三类差异、跨部门确认、变更复核、公司事实和可编辑价值测算。可自动播放、暂停、重播与键盘导航；全部效益数字明确为假设。
- 订单状态使用独立 `weave-order-demo-v1` 浏览器存储，兼容已有售前状态；不是多人共享数据库。
- 47 项规则测试通过；10 个路由及老板演示六幕已检查桌面与手机。老板演示、草稿编辑、确认、文件下载、变更、客诉和原售前循环均完成浏览器验证。
- 本地版本已验证；本轮远程 CI 和发布回执见 `docs/verification.md`，发布结果以实际 GitHub 记录为准。

## 下一轮优先事项

1. 邀请 `@0xrelander`，接受后验证实际写入权限及代码评审配置。
2. 由企业家或一线业务员按演示脚本试用，记录哪一步产生真实购买兴趣、哪一步仍依赖解释。
3. 取得一家公司脱敏产品与客户资料，比较现有 CRM 的实际效果。
4. 订单试点先取得一组脱敏 PO、报价、客户确认与变更资料，验证字段、判断和人工校正成本；不要扩展到全供应链自动履约。
5. 确定一个团队、一个资料入口及 ERP 交接字段，再设计真实权限、事件日志和持久化数据库。以确认耗时、遗漏和采用情况决定是否继续。

## 不应误读

界面中所有机会、回复和知识数量是演示状态统计。回款背调用于资料整理和交易条件建议，不等于真实信用评级或企业授信批准。产品机会不是已确定市场需求；负责人确认能力后才可成为产品事实。单个项目要求不能自动推广为该客户永久偏好。
